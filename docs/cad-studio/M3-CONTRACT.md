# M3 Build Contract — History: checkpoints, restore, ghost-diff

Binding contract for M3 (DESIGN.md §2.2 + §2.6), set by the coordinator. M1/M2 contracts remain
in force. The structural differ built here is M4's Review-mode engine — its record shape is a
public API, design it like one.

## Ownership

- **Builder A (server)**: server/src/differ.mjs (NEW), server/src/index.mjs (checkpoint store +
  endpoints), reference nothing else. No schema.mjs changes expected.
- **Builder B (Mat UI)**: server/public/edit.html, server/public/edit.js only.

## 1. Checkpoint store (A)

- Append-only JSONL at `designs/<slug>/history.jsonl` — one line per checkpoint:
  `{ "id": "cp-7", "author": "you" | "claude", "summary": "Moved Knuckle Guard",
     "ts": "ISO-8601", "base": "cp-6" | null, "design": { ...full snapshot... } }`
- ids monotonic per design (`cp-1`…). The file is NEVER rewritten or truncated — restore appends,
  it does not rewind. Corrupt/partial trailing line on read: skip it with a console.warn (crash-
  safe append). Missing file = empty history.
- Snapshot design must be validator-clean at write time (validate; if errors, reject the write
  400 — never persist a broken checkpoint).

## 2. Endpoints (A)

- `GET  /api/designs/:slug/checkpoints` → `{ checkpoints: [{id, author, summary, ts, base}] }`
  (chronological, no design bodies).
- `POST /api/designs/:slug/checkpoints` body `{ author, summary, design? }` — design defaults to
  the current draft (404 if no draft and no design). Appends, returns `{ id, ts }`.
- `GET  /api/designs/:slug/checkpoints/:id` → the full record.
- `POST /api/designs/:slug/draft/restore` body `{ checkpoint: "cp-3" }` → draft := that snapshot
  (rev bumps), APPENDS a new checkpoint `{ author: "you", summary: "restored \"<that summary>\"",
  base: "cp-3" }`, returns `{ design, rev, findings, checkpointId }`.
- `GET  /api/designs/:slug/checkpoints/diff?a=cp-2&b=cp-5` — `b` may also be the literal `draft`.
  Returns `{ changes: [DiffRecord] }`. Also `POST .../checkpoints/diff` with `{ a: <design>,
  b: <design> }` raw bodies (M4 will diff proposals that aren't checkpoints yet).

## 3. The structural differ (A) — server/src/differ.mjs

`diffDesigns(a, b) → DiffRecord[]`, identity-keyed, never index-keyed where ids exist:
parts by `id`, holes/slits by entry `id` (fall back to index only for legacy bare strings),
hardware/mechanisms/assembly instances by `id`, steps by index, scalar/meta fields by path.

```json
{ "kind": "added" | "removed" | "changed",
  "scope": "part" | "hole" | "slit" | "layout" | "path" | "count" | "hardware" |
           "mechanism" | "assembly" | "step" | "fitCheck" | "meta",
  "ref":  { "part": "sword-body", "holeId": null, "slitId": null, "id": null },
  "prop": "layout.x",                  // for scalar changes; null for geometry adds/removes
  "before": 0.35, "after": 3.25,       // JSON values; for paths, the path strings
  "label": "Sword Body: moved 2.9\" right"   // kid-language, generated by the differ
}
```
- Labels are the product surface (M4 chips reuse them verbatim): name the part, say what
  physically changed, quantify when cheap (moved X", turned N°, resized to W×H, hole grown to
  Ø…, N new score lines). Never emit JSON paths in labels.
- Unchanged objects produce nothing. A moved-only part yields layout records, not a path record
  (compare paths exactly; layout separately). Adding one hole to a part yields ONE added-hole
  record, not a changed-part blob.

## 4. Mat history strip (B)

- A slim horizontal strip (between verb bar and Toy Doctor): chronological author-colored dots —
  **you = kraft #9E8261, claude = crimson #A8214A** (M4) — plus a hollow "now" marker at the end.
  Hover: tooltip `summary · relative time`. Overflow: horizontal scroll, newest visible.
- Click a dot → popover: summary, author, absolute time, buttons **[Restore] [Compare]**.
  - **Restore** → POST draft/restore → mat/inspector/viewer refresh; new dot appears (the strip
    only ever grows); undo stack gets a snapshot so Cmd-Z steps back across the restore too.
  - **Compare** → ghost-diff mode vs the CURRENT draft: fetch diff (`b=draft`), then
    (a) dashed gray ghost of the checkpoint's differing geometry drawn under today's parts
    (old path at old layout for changed/removed parts; removed holes/slits as gray dashed),
    (b) crimson tint on today's added/changed geometry, (c) a right-side list of the diff labels;
    clicking a label zooms to its geometry (reuse Toy Doctor zoom). Banner "Comparing <summary> →
    now — [Exit]". While comparing, editing is locked (same affordance as the M2 pending lock).
    Clicking a different dot while in compare mode re-bases the comparison to that dot.
- Editing remains live-first: the strip reflects `GET /checkpoints` on load and after each write.

## 5. Checkpoint triggers + auto-summaries (B)

- Write a checkpoint (author "you") when: (a) 45s of inactivity follow ≥1 mutation since the
  last checkpoint; (b) SAVE; (c) PRINT; (d) `pagehide` via `navigator.sendBeacon` (best-effort).
  Never two checkpoints for zero intervening mutations.
- Auto-summary from the op log since last checkpoint, kid-language, most-significant-first, max
  ~60 chars: single op → specific ("Stretched Sword Body 2\" longer", "Punched Ø 0.26\" hole in
  Lid Wrap", "Turned Knuckle Guard 90°", "8 new score lines on Panel", "Added a Wheel from the
  Shelf"); multiple ops → "<most significant> +N more". PRINT/SAVE triggers append " · printed" /
  " · saved" only if they also carry mutations; otherwise no checkpoint.

## 6. Acceptance (verifier, timed, real gestures)

1. Regression: six designs validate 0 errors; M1 stretch-print-measure passes; M2 point 5 (Toy
   Doctor fix loop) passes.
2. Fresh /edit/pirate-sword: MOVE the guard 3" → wait for the debounce checkpoint → dot appears;
   tooltip reads a sensible summary naming the guard. history.jsonl has exactly cp-1 (+ its
   validator-clean snapshot).
3. Make a second edit burst (stretch blade + punch a hole) → second dot; then Restore cp-1 →
   geometry reverts on mat AND in a fresh draft-render PDF (Read it: blade back to original
   length); a THIRD dot appears ("restored …"); history.jsonl contains 3 lines, file strictly
   append-only (byte-prefix property verified).
4. Compare cp-1 → now: ghost of the old state + crimson current + label list; labels name parts
   in kid language with quantities; clicking a label zooms. Exit restores normal editing.
5. Kill and restart the server: checkpoints list survives (JSONL); draft is gone (in-memory, by
   design) and re-initializes from disk; restoring cp-2 still works.
6. Undo after a restore steps back across it (Cmd-Z returns the pre-restore state).
7. Zero console/page errors throughout (soft-mode rules from M2 respected); wall-time per flow.
