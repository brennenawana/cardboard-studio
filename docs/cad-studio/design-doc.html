Sheet 2 · Headline decisions

Five decisions carry the whole design

DECISION 1

Document: literal design.json, unchanged in role

One representation, literal coordinates only. No shape recipes, no params, no expressions — nothing that can cascade. One additive change: stable ids on holes and slits so diffs anchor on identity, not array position — and ids are the reference currency: mechanisms and fitChecks point at them, never at indices.

Why → Sheet 3
DECISION 2

History: append-only snapshots, never inside the file

Onshape’s version dots, not Fusion’s timeline. Every accepted change is a full-snapshot checkpoint {author, summary, base}; diffs are computed views; one uniform undo that also undoes the robot.

Why → Sheet 4
DECISION 3

Interaction: the Mat, six verbs that all work

A true-scale 2D canvas on the printed 1″ grid — screen = paper. MOVE / TURN / SIZE / COPIES / PUNCH / FOLD, Shape Shelf starters instead of drawing, live fold-up as the reward, Toy Doctor chips with one-tap fixes.

Why → Sheet 5
DECISION 4

LLM loop: symmetric editors, asymmetric commit rights

Claude reads the head document + selection + lint + recent history and returns a full modified file; the server validates, diffs against a recorded base, three-way merges, and stages a proposal. Nothing is ever silently applied.

Why → Sheet 6
DECISION 5

MVP: first playable needs zero new AI machinery

Milestone 1’s acceptance test: open a pirate-sword remix, drag the blade 2″ longer, slide FLAT→BUILT, print, hold a valid PDF — under 5 minutes, no chat involved. ~90% of the existing stack is reused untouched.

Plan → Sheet 8
Sheet 3 · Document model

One file, literal coordinates, nothing that can cascade

design.json stays the only document — the same file the validator, the toy-statics linter, both PDF renderers, and the 3D viewer already consume. The editor treats it as a flat, addressable scene graph: objects are parts, holes, slits, hardware, mechanisms, steps. A canvas drag is a property write; an LLM edit is a JSON edit; diffs are per-object, per-property — which is exactly what makes them renderable as chips and, later, partially acceptable.

Geometry is literal, always. Two seductive alternatives were killed by the judges:

No per-part shape recipes. Two judges independently ruled the dual representation fatal: a recompile-on-save precedence rule silently clobbers any hand or LLM edit to the raw path, and “cracking the egg” is a mystery box even with a warning dialog. Shelf starters keep their kid-friendly dials (wheel diameter, slit count, fit choice) at creation time only — the dial compiles immediately to a plain path and the dial state is discarded. Re-parameterizing later is a job for SIZE handles or the chat.

No params/expression block. All three judges killed it: expression strings inside numeric fields fork the schema contract, reintroduce cascade, and are a syntax — the thing this product exists to not teach. “Change one number, everything updates” is served by coherent stretch handles and, honestly, by asking Claude — whose dependent-feature recompute is exactly what a timeline automates, but reviewable. Verification-based parametrics: fitChecks re-verify, they never drive.

The one additive schema change, demanded by the round-trip judge — stable ids so an insertion at index 0 can’t corrupt diff attribution or re-aim a mechanism:

"holes": [
  { "id": "h1", "x": 2.5, "y": 0.6, "d": 0.6 },   // editor-assigned on first touch
  { "id": "h2", "x": 4.1, "y": 0.6, "d": 0.28 }   // diffs anchor on identity, not index
],
"mechanisms": [{
  "type": "revolute", "axle": "axle-dowel",
  "bearings": [ { "part": "body-core", "hole": "h1" } ],   // was "hole": 0 — id, never index
  "hubs":     [ { "part": "wheel-disc", "hole": "h2" } ]    // an inserted hole can't re-aim this
}]

Those ids are also the reference currency. mechanisms[] bearings/hubs and fitChecks historically named holes by array index ({"part": "body-core", "hole": 0}) — the exact positional-reference failure this decision exists to kill: an LLM inserting a hole would silently shift every mechanism’s meaning. Every cross-reference — bearings, hubs, fitCheck hole refs, anything future — points at a hole/slit id, never an index. The legacy index form stays readable during migration: the schema accepts both, the validator warns on indices, and the pipeline (linter resolution, spec examples, the ai.mjs prompt, the exemplar) migrates in M0.

Rejected at judgment Fusion-style operation history as truth (the file becomes a program the LLM must simulate) OpenSCAD code-first UI (the LLM already plays the programmatic role) A separate editor-native format (two sources of truth) A sketch-constraint solver (solver mystery vs. the linter’s plain sentences)

designs/<slug>/history/ holds the append-only log — full immutable snapshots, each with {author: "kid"|"parent"|"claude", summary, timestamp, baseCheckpoint}. Checkpoints are written on every accepted LLM proposal and on every debounced human save-pause, so it feels like game autosave. Diffs between any two checkpoints are computed by the same structural differ Review mode uses (build it once) and rendered as ghost geometry plus plain-language chips: “Blade: 12in → 14in”, “New part: Crossguard”. Branching collapses to the operation the studio already has: Remix duplicates the design folder into a new slug. The only scrubbable “timeline” a kid ever sees is the assembly itself — the existing FLAT⟷BUILT slider, where glue order drives build steps.

Rejected Fusion’s replayed timeline (its own community documents “models impossible to edit”) Onshape’s branch/merge graph UI (ceremony a 12-year-old doesn’t need) Diff-chains as storage (drift)
Sheet 5 · Interaction model

The Mat: screen = paper, six verbs, zero modes

One screen, /edit/:slug. The center is an SVG canvas in real inches, y-down, on the same 1″/3″ gray grid the printed cut sheets use — so the deepest CAD abstraction, units and scale, simply doesn’t exist. Snap at ¼″. On the left, the Shape Shelf: starters (Panel, Wheel, Strip, Blade, Tab) drag onto the mat and compile instantly to plain paths — nobody must draw a curve to make a part. Hardware chips (dowel, skewer, straw, string, brad, rubber band, paper clip) are drawn to true scale, so a dowel visually explains its own hole size. On the right, the existing Three.js fold-up in an iframe, re-fed the working document. Along the bottom, the Toy Doctor lint strip and the chat rail.

Rules the judges made non-negotiable: the verb set shown equals the verb set that works — FOLD ships in v1, and GLUE/DOWEL are not toolbar verbs, so no stub buttons exist. No anchor dots by default — freeform point-edit is the one pro tool, behind an explicit double-click, never the default rendering of a selected part. No modes, no overloading — MOVE, SIZE and point-edit are distinct verbs, not three behaviors of one drag, and TURN exists. The Toy Doctor runs the validator and statics linter continuously; chips pin to the offending geometry in both panes, phrased as shop rules (“this axle wobbles — bearing is shorter than 2× its width”). Where the linter can compute a fix, the chip carries a one-tap deterministic fix — deterministic fixes stay deterministic and visible, never robot magic. Where it can’t, the chip offers “ask Claude to fix”. And the first run is a remix, not a blank page, opened with a three-line goal card — you met it at the top of this page.

Assembly in v1 is a drag-to-reorder Build Order list plus chat placement (“put the guard on the grip”). No numeric nudge fields — typing coordinates is the abstraction this product exists to remove.

Sheet 6 · Human ⟷ LLM loop

Same file, same door — only the human commits

You already ran this loop in Sheet 1 when you pressed “make it fiercer” and watched the ghost overlay, the JSON diff, and the Keep/Nope buttons. Here is what each stage does in the real system.

READ

Claude sees what you see

Each turn sends the current design.json, the spec context ai.mjs already uses, the selection + current lint output (“kid has guard-bowl selected, lint says curl too shallow”), and the last few checkpoint labels + diffs so it knows what the humans just did by hand. The head checkpoint hash is recorded as the proposal’s base.

EDIT

Full-document replace, deliberately

Claude returns prose or a complete modified design.json. LLMs botch positional patches, the docs are 18–38 KB, and the server owning the diff is what makes everything downstream possible.

VALID

The existing validate/repair loop runs first

Server-side, before the kid ever sees the proposal. Failures are auto-repaired or rejected.

MERGE

Three-way merge at the property level

Against the recorded base, with stable ids as anchors — unrelated edits never conflict, so a kid edit during LLM thinking is never lost. A true same-property conflict renders as a two-ghost picker in kid language: “You made the blade 14in, Claude made it 16 — tap the one you want” (default: keep yours). “Re-diff with a badge” without a recorded base was ruled fatal — it can attribute the kid’s own edit to the robot.

REVIEW

Ghosts, chips, and a lint verdict

The Mat shows before-geometry as dashed gray ghosts under the proposal’s ink; changed parts pulse; kid-language chips highlight their geometry in 2D and 3D; a banner says “still passes all 8 toy checks” or shows what broke. The 3D pane gets the whole proposal document with a BEFORE/AFTER toggle — never a dual-document ghost render inside the 985-line viewer. The ghost-diff is the pedagogy: every accepted robot edit shows which handles would have done it by hand.

COMMIT

Accept writes head + a checkpoint authored “Claude: …”

Reject discards. v1 is whole-proposal accept/reject; part-group Keep/Nope is milestone M5 — and the diff/merge machinery shipped in v1 already supports it, so no rework.

Rejected Silent/live LLM co-editing (destroys authorship and the learning channel) JSON-patch wire formats Full CRDT multiplayer (one family + a turn-based robot) No-concurrency-story (a kid edit during LLM thinking must never be lost)

Sheet 8 · Judgment calls & roadmap

Who was overridden, and why

Eight places where concepts or judges disagreed and someone had to lose. The pattern: buildability and round-trip safety outrank elegance and completeness.

C1Gen recipes: removal beat repair
Judge 1 asked to fix crack-the-egg with an explicit dialog; Judges 2 and 3 ruled the dual representation itself fatal. Overrode Judge 1’s repair in favor of removal — with no persisted recipe there is nothing to crack, which also satisfies Judge 1’s underlying nothing-surprising rule.
C2Partial acceptance: v1.x, machinery in v1
Judge 2 wanted part-group Keep/Nope in the MVP; Judge 3 ruled that a fatal scope flaw. Overrode Judge 2 on timing only: whole-proposal accept/reject ships first (M4), Keep/Nope is the immediate next milestone (M5) — and Judge 2’s mechanism demands (base hash, stable ids, property-level differ, three-way merge) are all in v1, so no rework.
C3FOLD ships in v1
Concept A deferred BEND; Judge 1 ruled visible-but-broken verbs fatal. Sided with Judge 1: the FOLD slit tool ships in M2 — scoped to slits[] only, so Judge 3’s veto of the 2D fold-angle dial holds too.
C43D proposal preview: toggle, not ghosts
Judge 1 grafted a simultaneous kraft/blue ghost + hold-to-peek in 3D; Judge 3 ruled dual-document rendering inside viewer.js a fatal repaint. Overrode Judge 1’s rendering detail: a BEFORE/AFTER toggle feeding the whole proposal doc to the unmodified viewer delivers the same comparison at zero viewer cost. 2D keeps the full simultaneous ghost overlay — where the pedagogy lives anyway.
C5The lint “Fix it” button: partitioned
Judges 2 and 3 grafted hand-the-check-to-Claude; Judge 1 ruled LLM-mediated deterministic fixes fatal. Both survive, partitioned: computable fixes are one-tap deterministic and visible; only non-computable checks get “ask Claude to fix”.
C6No numeric assembly nudge
A’s v1 fallback was typed coordinates; Judge 1 ruled that fatal. Sided with Judge 1: v1 assembly fallback is the Build Order list + chat placement only.
C7Verb naming: split the difference
C’s material verbs are the best idea in the field, but “score” and “laminate” as labels are a hidden tutorial. PUNCH and FOLD keep material names because kids’ hands know them; SCORE becomes FOLD’s rendering, LAMINATE becomes a plain stepper in the inspector.
C8No viewer refactor in v1
B made a build(design) extraction a v1 prerequisite; Judge 3 vetoed. Sided with Judge 3: iframe + draft endpoint in v1; refactor only if debounce latency demands it.
