Cardboard Studio · Project Overview · Aug 2026

Cutting Mat

The Cardboard Studio CAD — what we're building, why it's shaped this way, and the order we'll build it in. Written for future-us, before the first MVP commit.

The tool in one breath: a structured, direct-manipulation editor over the existing design.json — a 2D cutting mat that is literally the printed template, a live 3D fold-up pane, and a chat rail where Claude proposes reviewable edits to the same file. No new format, no parametric timeline, no expressions, nothing that can cascade. The worst outcome of any edit, by any hand, is a colored lint chip with a sentence — never a broken recompute.

Part A — Where we start

The studio today

Cardboard Studio is a local family server (localhost:4177): a parent and kid dream up a toy in chat, the local claude CLI generates a design.json through a validate/repair loop, and the renderers print a Reuse & Play–grade bundle — actual-size cut sheets on a 1-inch grid plus an illustrated assembly guide. Six designs have shipped this way, all flat parts + folds + hardware; designs/pirate-sword/ is the hand-crafted exemplar and the AI's few-shot example.

The pipeline

The 3D viewer

Three.js fold-up: extrudes real cut paths, folds via a hinge tree, FLAT⟷BUILT slider with step ticks, hardware as wood cylinders, ROLL toggle.

schema.mjs

The toy-statics linter

Measures real geometry: bearing/hub fit bands, bearing length, axle budget, wheel sweep, tipping ratio, durability rules. Toys must work, not just look right.

Quality bar: the gauntlet. Blind critics compare our output against real Reuse & Play PDFs and name the biggest gap; builders fix; repeat until ours wins. Criterion: which one could a parent and kid actually build from — never branding.

Part B — Why a CAD

What Cutting Mat adds

Today the only way to change a design after generation is editing JSON by hand or re-rolling the AI. Cutting Mat closes that gap without betraying what the studio is for:

Functional toys

Designs are working machines, not shapes — axles spin, wheels roll, lids close. Every edit stays under the same statics linter, live, as Toy Doctor chips pinned to the offending geometry.

First principles

Screen = paper: the Mat is drawn in real inches on the same 1" grid as the printed sheets, so the deepest CAD abstraction — units and scale — simply doesn't exist. Verbs are the ones kids' hands already know (PUNCH, FOLD). Checks explain in shop-rule sentences; no syntax, no solver, no mystery box. This product exists to not teach a syntax.

Kid + parent + Claude

Symmetric editors, asymmetric commit rights. All three hands edit the same file through the same validated door; Claude only ever stages proposals the kid reviews as ghost overlays — and every accepted robot edit shows which handles would have done it by hand. Nothing is silently applied.

The five headline decisions

  1. Document: design.json unchanged in role, literal coordinates only. No gen recipes, no params/expressions. One additive schema change: optional stable ids on holes and slits, so diffs anchor on identity, not array position — and ids are the reference currency: mechanisms and fitChecks point at hole/slit ids, never indices (legacy index refs stay readable during migration; the validator warns).
  2. History: append-only full snapshots per design, never inside the file. Every accepted change (human or LLM) is a checkpoint {author, summary, timestamp, baseCheckpoint}; diffs are computed views; one uniform undo that also undoes the robot.
  3. Interaction: the Mat — a true-scale 2D canvas, six working verbs, Shape Shelf starters instead of drawing, live 3D fold-up as the reward loop, Toy Doctor chips with one-tap deterministic fixes. Every verb shown on screen works on day one.
  4. LLM loop: Claude reads head doc + selection + lint + recent history, returns a full modified design.json; the server validates, records the base checkpoint hash, computes a structural diff, three-way merges, and stages a proposal the kid reviews. Only the human commits.
  5. MVP cut: first playable requires zero new AI machinery — remix a pirate sword, drag the blade 2" longer, slide FLAT→BUILT, print a valid PDF, under 5 minutes, no chat involved.

Six verbs, all functional in v1

MOVEdrag, snaps at 1/4"→ layout position
TURNrotate handle→ orientation
SIZEcorner/edge handles, live inch readouts, coherent scale→ part.path
COPIES×N stepper; laminated stacks are big N→ count / laminate
PUNCHclick a spot → hole with a fit chooser: “LOOSE so it spins” / “SNUG so it grips,” diameters straight from the linter's bands→ holes[]
FOLDdrag a line → dashed score; CURL helper fans N parallel lines. Angles stay owned by assembly folds→ slits[]

The pro tool — freeform point-edit — hides behind an explicit double-click, never the default. First run is a remix with a three-line goal card, not a blank page.

Part C — Build order

MVP roadmap

~90% of the stack already exists. Each milestone lands something a kid can touch; the diff machinery is built once (M3) and reused (M4, M5).

  • M0

    Draft plumbing + id-reference migration

    In-memory working-draft endpoint per open design (GET/PUT /api/designs/:slug/draft); the 3D viewer embeds via iframe pointed at the draft — zero refactor of viewer.js. Plus the reference migration: schema.mjs accepts hole refs by id ({"hole": "h1"}) alongside the legacy index form and warns on indices; the linter resolves both; the AI prompt and the pirate-sword exemplar move to id refs.

  • M1

    First playable

    /edit/:slug: SVG Mat rendering parts from design.json (path math ported from geometry.mjs), MOVE/TURN/SIZE/COPIES, selection-synced parts tray, inspector, grid, Print button calling the existing PDF renderers.

    Acceptance test — also the first-run scriptRemix pirate-sword → drag the blade 2in longer → slide FLAT→BUILT → print → hold a valid PDF. Under 5 minutes. No AI machinery.
  • M2

    Cardboard verbs + Toy Doctor

    PUNCH with the two named fits from the linter's bands; FOLD slit tool + CURL helper; Shape Shelf starters (server-side pure functions → plain paths); continuous lint chips pinned to geometry with one-tap deterministic fixes; goal card; stable-id assignment on edit.

  • M3

    History

    Checkpoint writes on accepted proposals + debounced saves; history strip of author-colored labeled dots (“You: moved wheel hole” / “Claude: lengthened blade”); restore; two-checkpoint ghost-diff view.

    The structural differ is built here and shared with M4's Review mode — build it once.

  • M4

    Chat proposals

    ai.mjs “edit this design” mode with selection + lint + history context; base-hash recording; per-object/per-property differ (~150 lines); three-way merge with the two-ghost conflict picker; Review mode with whole-proposal accept/reject, kid-language chips, before/after 3D toggle; “ask Claude to fix” on non-deterministic lint chips.

  • M5 · v1.x

    Then, in order

    Part-group Keep/Nope partial acceptance → checkpoint thumbnails → laminate section view → 3D place-and-snap assembly (face-to-face, hole-onto-axle) with glue-order auto-writing steps → mirror/symmetry tools.

Architecture: one document, one validated door

Part E — Held open

Decisions we are deliberately not making yet

  • params / expressions in the document — killed for v1 and v1.1 by all three judges; not reconsidered until literal-coordinates + LLM-as-parametric-engine demonstrably fails a real family.
  • Persisted shape recipes of any kind — same bar. Shelf dials exist at creation time only, then compile to plain paths.
  • Realtime co-editing / CRDTs — one family plus a turn-based robot needs base-hash merge, not Figma's sync engine.
  • Branch/merge UI beyond Remix-a-copy (folder duplication, the studio's existing pattern).
  • A 2D constraint solver — fitChecks that verify and flag beat constraints that drive and fight the kid's drag.
  • 3D face-snap GLUE / DOWEL-as-a-verb — v1.x (M5); until then assembly flows through the Build Order list and chat. No stub buttons in the meantime.
  • fitCheck authoring UI — the LLM writes fitChecks when asked to “lock” a relationship.
  • Editing steps / hero on canvas — remains Claude's job via chat; it is already good at them.
  • Checkpoint thumbnails — labeled, author-colored list first; thumbnails need a renderer we refuse to build before M5.
  • Freeform bezier pen as a primary tool — point-edit stays behind double-click; Shelf + SIZE + chat cover shape creation.
  • New mechanism types beyond revolute — the linter and viewer define what exists; the editor surfaces, never invents.
